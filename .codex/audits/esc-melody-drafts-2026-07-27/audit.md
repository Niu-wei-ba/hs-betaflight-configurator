# 电调音草稿流程审查

## 范围

- 页面：独立电调音菜单，离线编辑状态
- 流程：新建、命名、空名称校验、编辑、切换、重命名、保存预置、RTTTL 编辑后保存
- 视口：1280 x 720
- 未覆盖：真实 ESC 扫描、写入、多路通道切换、屏幕阅读器实测

## 流程健康度

1. 草稿入口与空状态：一般。入口存在，但加号较小，空状态不解释草稿保存方式。
2. 新建命名弹窗：良好。输入框自动聚焦，重命名时会全选原名称。
3. 空名称校验：一般。错误可见，但创建按钮在无效状态仍可点击，提交后焦点停留在按钮。
4. 新建结果：较差。空草稿已写入本地，但页面仍显示“保存草稿”，没有已保存/未保存状态。
5. 编辑草稿：危险。编辑后草稿高亮消失，没有未保存标记。
6. 切换再返回：危险。未保存的音符修改直接丢失，没有确认或恢复入口。
7. 从预置保存：较差。绕过命名弹窗，直接创建以预置名称命名的草稿。
8. 重复保存：危险。同名检查只覆盖新建/重命名弹窗，底部保存可产生多个完全同名草稿。
9. RTTTL 编辑后保存：危险。代码编辑会丢失当前草稿身份，保存时再创建一个同名草稿。

## 优化清单

| 优先级 | 问题 | 建议 |
| --- | --- | --- |
| P0 | 编辑后切换会丢失修改 | 草稿编辑采用 300-500 ms 防抖自动保存；若坚持手动保存，则切换预置、草稿、ESC 或离开页面前必须确认。 |
| P0 | RTTTL 编辑会从当前草稿脱离 | 卷帘和代码编辑始终共享同一个草稿 ID，编辑来源改变不应清空 `currentDraftId`。 |
| P0 | 底部保存绕过命名和同名校验 | 无草稿 ID 时改为“另存为草稿”并打开统一命名弹窗；有草稿 ID 时才显示“保存更改”。 |
| P1 | 当前草稿编辑后失去选中高亮 | 草稿保持选中，并增加“未保存”圆点或“已自动保存”状态，不要用取消选中表示内容变化。 |
| P1 | 新建空草稿已持久化，但保存模型不明确 | 明确选择自动保存或手动保存，不要混用；推荐本地草稿自动保存，ESC 写入仍保持显式安全流程。 |
| P1 | 空草稿显示英文错误和 `4/128 B` | 错误改为中文“请添加至少一个音符或休止符”；空草稿显示 `0/128 B`，或明确说明 4 B 为编码头。 |
| P1 | 没有删除、复制或导出 | 每条草稿增加更多菜单：重命名、复制、导出 RTTTL、删除；删除需要确认。 |
| P1 | 最多 20 条时静默丢弃最旧草稿 | 达到上限时明确提示并阻止继续创建，或提供草稿管理；不得静默删除。 |
| P2 | 列表只显示日期，重复条目无法区分 | 增加音符数、时长、最后编辑时间；同名草稿从所有入口统一阻止。 |
| P2 | 新建空草稿后撤销按钮立即可用 | 新建文档应重置撤销历史，不应允许一次撤销跳回上一个预置。 |
| P2 | 空名称时主按钮仍可点击 | 名称为空或重复时禁用主按钮；提交错误后将焦点移回输入框，并通过 `role=alert` 宣告错误。 |
| P2 | 加号与重命名目标较小 | 加号至少增至 28-32 px；为键盘焦点提供明显轮廓，重命名按钮保留可访问名称。 |
| P2 | 模态弹窗背景仍在辅助技术读取树中 | 打开弹窗时令背景 `inert`，加入焦点循环，并在关闭后把焦点返回触发按钮。 |
| P2 | 草稿仅存浏览器本地存储 | 提供草稿包导入/导出，明确“清理浏览器数据会丢失草稿”。 |

## 推荐实施顺序

1. 统一草稿身份与保存模型，先修复丢失和重复。
2. 统一“新建 / 另存为 / 保存更改”三个动作及同名校验。
3. 增加脏状态、自动保存状态和切换保护。
4. 补齐删除、复制、导入导出和 20 条上限处理。
5. 最后处理空状态文案、元数据、点击目标与弹窗无障碍。
