# Project Firmware Distribution Goal

本 skill 是当前项目“一期固件分发系统”的目标基线。

在以下场景优先使用：
- 设计或调整固件分发架构
- 编写 GitHub Actions 同步/预构建流程
- 设计 COS 目录、生命周期或 CDN 分发策略
- 开发固件版本索引、下载地址、任务状态等 API
- 改造 BFC 前端的固件列表、下载或刷机入口
- 讨论热资源、温资源、冷资源的缓存和回源策略

## 一期目标

一期不是做全量固件镜像库，而是做 BFC 可用的国内加速固件分发系统。

核心策略：
- GitHub Actions 负责海外侧拉取、预构建、metadata 生成和上传
- COS + CDN 负责国内存储与分发
- 冷门资源按需回源，成功后回填缓存
- 常见请求优先走国内直出，不依赖用户侧直接访问 GitHub

## 一期边界

优先做：
- 热门版本和热门 target 的定时预热
- metadata 索引生成
- COS/CDN 下载直出
- 未命中时的冷门回源和缓存回填

一期不强行做：
- 全量固件长期存储
- 大规模实时在线构建平台
- 把 GitHub-hosted runners 当长期在线任务系统

## 使用方法

1. 先按本 skill 的目标和边界约束方案。
2. 需要详细架构、目录、API、流程或生命周期规则时，读取 [references/phase-one-plan.md](references/phase-one-plan.md)。
3. 如果任务是具体开发实现，应确保设计不偏离“一期先热后冷、国内分发优先、冷门按需回源”的主线。

## 决策原则

- 常见请求优先命中 COS/CDN，降低 GitHub 依赖。
- 预构建范围必须收敛，只覆盖热门版本和热门 target。
- 冷门资源优先做回源缓存，不默认升级为实时构建。
- 目录、索引和生命周期规则要从一开始就可运营，避免后续清理困难。
- 热度统计必须尽早落地，为后续热门集调整提供依据。

## 交付顺序

- 第一阶段：热资源直出
- 第二阶段：冷门回源
- 第三阶段：动态构建、任务去重、海外构建服务等高级能力
